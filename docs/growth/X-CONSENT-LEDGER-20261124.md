# CAI-X-GROWTH@1 — isolated consent and invoice ledger

Scope: disposable PG17 fixture only. The private schema persists a server-issued nonce digest, fixed acquisition tuple, grant/expiry, one-time confirmed auth.users registration, withdrawal, unique initial invoice and subscription HMACs, and terminal reversal. A service-only narrow RPC checks authoritative registration timestamps and serializes payment intake against withdrawal; anon/authenticated and direct service-role table access are denied. Existing real CI PostgreSQL restart also checks persisted withdrawal and reversal. The private schema is NOT a production migration or an exposed Data API schema. The dedicated trusted server still needs a protected session/nonce and explicit purpose-specific affirmative consent. Generic analytics consent or a browser UTM does not suffice.

The existing purchase receipt handler gains an optional injected observer after verified live paid initial invoice, authenticated same-user receipt, catalog, charge, refund and dispute checks, with confirmed email and actual Stripe paid_at. A dedicated HMAC key (not the Stripe secret) normalizes invoice/subscription identifiers. The production server supplies no observer. No new provider calls, secrets, schema activation or routes; no tracking before consent. The isolated store counts only recorded candidates, excludes revoked/expired/reversed and stale rows, and never represents a complete authenticated cohort. Receipt reads older than 24h need current reconciliation; reversal delivery and reconciliation must be implemented before claiming live metrics.

Before production: review explicit conversion purpose and notice version, implement server-authenticated protected grant and withdrawal, secure signup callback binding and nonce lifecycle, key rotation/retention/deletion, true Supabase least-privilege adapter/advisors, fresh Stripe reconciliation and coverage proof, owner-only aggregate readback and existing LangGraph integration. Verify isolated production recovery (#664); never enable without separate authorization. Rollback revert inactive source-only slice; never remove live consent records without a lawful retention/deletion plan.
