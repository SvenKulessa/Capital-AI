# CAI-X-GROWTH@1 — conversion evidence candidate contract

Source-only slice, no production migration or provider calls. #951 emits a consented landing event, not a registration receipt. #953 reads session UTM aggregates, not user-level attribution. Existing CookieConsentV3 is a browser preference receipt, not a durable server-side proof. Existing purchase-receipt.mjs verifies live initial paid invoice and charge ownership/refund/dispute, but has no acquisition campaign link. Do not infer a link from either source or retrofit user metadata from an untrusted browser.

The new reconciliation contract accepts only campaign-bound, pseudonymous candidate receipts, requiring analytics purpose, valid consent at registration and at report time, matching signup proof, a fresh live initial paid EUR invoice, unique subject/invoice/subscription identifiers, and no refunds/disputes. The result contains candidate counts only, no identity or raw provider records. Actual registrations, paid subscriptions and revenue remain null. Imported evidence is NOT_AUTHENTICATED; the graph cannot promote it or grant cost authority. Existing offline graph CLI accepts --conversion-data; its output is a gap review, not a runtime or provider readback.

Remaining: server-authenticated consent grant/withdrawal and one-time acquisition receipt bound to verified signup, dedicated pseudonym secret and purpose-specific retention, Stripe receipt adapter bound to the same subject and initial invoice, full-cohort coverage and freshness evidence, owner-only aggregate route and Control Center integration. No additional tracking, OAuth, production DB mutation or paid activation. Privacy notice/purpose review and isolated recovery are required before a durable linkage is activated. Avoid exporting any subject keys. No production migration or new scheduler in this slice. Rollback: revert code and tests.
