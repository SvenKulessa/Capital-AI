## Standalone product scope

The dedicated repository contains:

- CADS Starter / Pro / Enterprise tier and capability contract;
- CADS Marketplace runtime and tests;
- CADS commerce/entitlement boundary;
- CADS observability;
- bounded HTTP-security helpers required by the runtime;
- Marketplace registration/plan manifests;
- Supabase Marketplace entitlement migration;
- source/transformation provenance tooling;
- CADS product/license/third-party notices;
- security, privacy, support, B2B terms and installation documentation.

The standalone repository intentionally separates the CADS tier/capability contract into
`packages/cads-core/`.

## Not CADS release evidence

The standalone CADS release gate does **not** depend on infrastructure comparison results.

In particular, the following are not inherited as CADS PASS:

- NATS versus Kafka comparison benchmarks;
- Go/Golang benchmark claims;
- Rust versus Node comparison claims;
- `CAPITAL_AI_EVENT_BACKBONE@1` comparison results.

The unsuccessful NATS/Go path is not valid CADS release, Marketplace or Production evidence.

If a future CADS feature explicitly promises event-backbone benchmarking, that feature requires its
own reproducible evidence and separate PRODUCT/PLATFORM/TRUST admission.

## Explicitly excluded

- MARKET provider adapters, provider credentials and market-data rights;
- NATS/Valkey infrastructure unless a future standalone feature explicitly requires and admits it;
- JaJa/Chat Buddy assets;
- Social Media Engine;
- unrelated Capital-AI web UI;
- SEO/GROWTH code;
- owner/admin control-center code;
- secrets and runtime credential values;
- unrelated third-party dependency inventories.

## Export identity

Capital-AI source provenance is generated by:

`npm run evidence:cads-export`

`CAPITAL_AI_CADS_EXPORT_PROVENANCE@1` binds the exact Capital-AI source candidate.

The organization repository additionally owns
`CAPITAL_AI_CADS_STANDALONE_SOURCE_MANIFEST@2`, which distinguishes:

- byte-identical source files;
- explicit standalone transformations;
- standalone-only files/tests;
- intentionally excluded benchmark-only infrastructure scope.

A Capital-AI package PASS must never be copied into the standalone repository as an inherited PASS.

## Standalone revalidation

For every delta exported from Capital-AI, the organization repository must independently verify:

1. source/transformation provenance;
2. CADS tier/capability contract tests;
3. Marketplace webhook, OAuth and entitlement tests;
4. Supabase RLS/service-role/idempotency tests;
5. secret-like material scan;
6. dedicated artifact/container build when a deployable artifact is introduced;
7. SBOM;
8. vulnerability scan;
9. runtime license inventory;
10. non-root/read-only/cap-drop smoke where applicable;
11. real Marketplace installation/configuration/purchase lifecycle before publication.

Security, licensing, Production and GitHub Marketplace publication remain separate gates.
